# 汎用対話データ生成：話題提起仕様

## 生成数と割り当て

- 話題ドメインは T01〜T15 の15種類とする。
- 各話題ドメインにつき、15,000件のテキスト対話を生成する。
- 全体では225,000件を生成する。
- 各ドメインの15,000件を、そのドメインに属する話題提起文へ均等に割り当てる。

## 話題提起文の固定規則

- 一覧の話題提起文を会話冒頭に使用する。
- 話題提起文の内容や言い回しを LLM に言い換えさせない。
- LLM が加えてよい変化は、自然なフィラーと言いよどみだけとする。ただし読点「、」を連続させず、言いよどみはフィラーの言葉で表す。
- 通常は、A が一覧の話題提起文を発話して会話を開始する。
- B が A の挨拶に割り込んで挨拶を返す形も許可する。この場合は、A の発話を挨拶部分の直後で分割し、B の挨拶を挟んだ後、A が残りの話題提起部分を続ける。
- 割り込みがあっても、A の分割前後を連結した基準文は一覧の固定文と一致させる。フィラーと言いよどみだけは例外とする。
- 原則として対話中のアルファベットは禁止する。ただし全話題で`SNS`、`YouTube`、`URL`、`ICT`、`DIY`、
  `Tシャツ`、`AI`、`IT`、`BGM`、`ビタミンC`、`DM`、`CM`、`Amazon`、`Web`、`OS`、`Google`、
  `Switch`、`RPG`を、T09ではさらに話題に必要な`VR`、`AR`を例外として許可する。許可語は全角や
  大小文字の揺れが出ても、保存前に
  ここに記載した半角表記へ統一する。
- LLM が連続読点を出した場合も、保存前の後処理で1個の読点へ正規化する。正規化後に `、。` などが生じる場合は文末記号だけを残す。

例：

```text
A: こんにちは、
B: こんにちは
A: 何か趣味はありますか？
```

## 話題への乗り気度

- 「乗り気」「普通」「あまり興味がない」の抽選比率を `5:5:1` とする。
- 「あまり興味がない」の呼び出し回数は、「乗り気」または「普通」のそれぞれ5分の1とする。
- 15,000件単位では完全には割り切れないため、ドメイン全体で可能な限り比率へ近づける。目安は次のとおり。
  - 乗り気：6,818件前後
  - 普通：6,818件前後
  - あまり興味がない：1,364件前後
- 話題からの逸脱は乗り気度で制御する。
  - 乗り気：主に提示された話題の中で積極的に話す。
  - 普通：提示された話題を中心に、自然な関連話題への展開を許す。
  - あまり興味がない：会話自体は拒否しないが反応は短めにし、B が関心を持つ別の話題へ自然に移ることを許す。
